# アセット可視領域監査

## 目的

画像ファイル全体の寸法ではなく、アルファチャンネル上の可視領域を基準に描画する。これにより、透明余白や切り出し位置が異なる画像でも、見かけの大きさ・中心・足元を統一する。

## 2026-08-15 監査結果

- 対象: `assets/generated-v4.json` に登録された134画像
- 主人公16画像のファイル寸法: すべて142×257px
- 主人公の実際の可視高: 211～235px
- 方向による最大差: 24px、約11%
- 原因: 共通キャンバスの寸法は揃っていたが、画像内の透明余白と人物自体の縮尺が揃っていなかった

## 実行時の補正

- `assets/asset-metrics.js` のアルファ境界だけを切り出してCanvasへ描画する
- 主人公は全方向を可視高44論理pxに統一する
- 地面との接地点は可視領域の下辺中央に統一する
- 資源・敵・建物も同じアルファ境界処理を通す
- DOM上のアイテム・建物・UI画像は、可視領域が要素中央へ収まる背景位置と倍率を計算する

## 再監査

画像の追加・再生成後は、プロジェクト直下で次を実行する。

```powershell
python tools/audit_assets.py
```

生成物:

- `assets/asset-metrics.json`: 人間が確認しやすい監査データ
- `assets/asset-metrics.js`: ゲーム実行時に読み込む同内容のデータ

`?selftest=1` は、全登録画像に有効な可視領域と足元基準データが存在することも検証する。
