# 完成後の独立レビューと適用結果

3担当を独立して起動し、最初は読み取りのみでゲーム・UI・描画をレビューした。再現可能な不具合と設計範囲内の具体的な追加・改善を適用し、担当ごとに再確認した。既存の別ゲームは参照・変更していない。

| 担当 | 指摘・追加要素 | 適用した変更 |
| --- | --- | --- |
| エンジン | 大量クラフトの落下スタックが保存上限を超える | 上限ごとに分割し、100個の松明が99+1で保存されることを確認 |
| エンジン | 未来の時刻のロックが失効しない | 有限な時刻・0以上8秒以内の経過を検査。App側の判定も一致 |
| エンジン | 不正位置の祭壇を含むJSONで操作時に例外 | 固定祭壇の位置を検証し、操作時にもガード |
| エンジン | 満腹・満HP時にバフ料理を事前使用できない | 未付与・短くなったバフを料理の必要性に含める |
| エンジン | 大規模な建築・植樹から保存上限を超える | 炉心の重複セルを除外して設置上限を守り、死亡袋1枠を予約 |
| UI | 実キーと定義・説明の不一致 | K=調べる、L=回避、G=記録、Tab/I=持ち物で統一 |
| UI | 保存失敗から別記録へ移り進行を失う | 失敗と永続不可を確認し、JSON退避・明示的破棄を選べる画面へ。新規開始・終了にも適用 |
| UI | 現在スロットのバックアップを読み込む前に上書き | 同じスロットの復元では現行状態を保存し直さない |
| UI | 取り込み・削除の操作権を作業時に再確認しない | 保存直前の所有確認、別スロットでは一時ロック取得と解放 |
| UI | 削除失敗を成功として通知 | ストアの返り値を検査 |
| UI | BFCacheから復帰すると自分のタブが所有権を失う | キャッシュ退避時に所有を維持し、復帰時に最新所有者を再確認 |
| UI | スマホでレシピ詳細が長いリストの下に隠れる | レシピ一覧に高さ制限と独立スクロールを追加 |
| UI | 作成個数を作成回数として表示 | 生成した個数の表記に修正 |
| UI | 選択装備・自動切り替え・ツルハシの攻撃力と能力表示がずれる | 実エンジンの `getEquipmentStats()` をUIへ提供 |
| 描画 | 輪の危険域の内外半径が実判定と異なる | r±width/2と安全な扇形を一致させ、予告強調も適用 |
| 描画 | 輪の大量の矩形描画でフレームが遅い | 走査線の連続区間で描画。独立測定で60フレーム2471.8ms→218.7ms（同一Chrome検証） |
| 描画 | 鏡像ボスの本体の周期的な手掛かりがない | 本体だけ短い周期窓で煌めき、動き低減時は固定表示 |
| 描画 | 空・育苗・成熟・暗い苗床、茸の幼体が同じ | 作物4種と成長段階、空の土、暗さ、採れる印、幼体を描き分け |
| 描画 | 自然鉱脈・門・結界・建築素材が汎用表示 | 石炭・硬岩・黒曜・ルーン・木/石/ガラス/レンガ/金の壁床と石橋を追加 |
| 描画 | 画面揺れ設定が効かない | 短い整数座標の揺れを実装し、OFF・動き低減時は停止。入力座標も補正 |
| 音 | 灼熱と結晶のbiome番号を取り違える | 実データの1/2/3に音楽を対応 |

統合時にも、古いタブのリース復活、ドットが不均等になる地図縮小、原画リクエストの過多、二重の命中演出、持っていない剣の表示、裂け目が水に見える問題を修正した。原画370枚は補間せず1枚のアトラスに梱包している。

再レビューでは各指摘の修正が確認され、担当の調査範囲内に未解決の具体的な問題・追加要素は残っていない。検証内容と実行時間は `validation.json`、再現可能な検証は `../tests/review_*_probe.py` にある。レビュー全体の開始時刻・トークン使用量は取得できていないため、実測値として記載しない。

検証はスクリプトとChromeで実施している。あらゆる端末での動作や、将来考えられる全機能の網羅を保証するものではない。通常の採集・クラフト・農業・釣りと戦闘状態遷移を動かし、討伐条件を確認する箇所には固定ダメージの検証用操作を使った。
