実装は3ファイルとも書き終えました。ただし実行・動作確認は一切できていません（この環境ではファイルの読み書きしかできないため）。

## 実装したもの
- **`index.html`**: 共通CSS、`style.css` の順に読み込み、`game.js` は `defer` で読みます。ES module は使っていないので `file://` でそのまま開けます。ヘッダー、3列の温室レイアウト、実績・遊び方・設定のタブ、確認ダイアログ、帰還ダイアログ、最下部のクレジットを入れました。設備アイコンは inline SVG です。
- **`style.css`**:
  - 共通CSSの影響を避けるため、`body.ssg` 配下で button・見出し・ランドマークを明示的に上書きしています。
  - PC（900px以上）は 220〜280px のカード＋中央の温室（`garden-bg.svg` を cover 表示、植物は大きく表示）です。
  - スマホは温室 → 収集 → 収穫（可能時）→ 育成 → 設備の順で、下部に固定タブがあります。
  - 動きは `html[data-motion="full"]` のときだけ有効にしています。
- **`game.js`**:
  - DESIGN.md の機能はすべて入れました。8実績、5段階の成長表示、収穫、reduced-motion の設定、aria 属性、dialog のフォーカス制御（トラップと復帰）も含みます。
  - 保存は `starsprout.v1` に設計書どおりのデータ構造で書き、`settings` だけ追加しています。操作時にも保存します（購入・収穫は即時、タップは約0.8秒まとめ）。
  - 保存データは型・有限性・非負・整数・`ver`・上限を検証します。不正なら `.bak` に退避して初期化し、通知します。
  - `localStorage` が使えない環境でもプレイでき、「保存不可」を表示します。
  - 時間の進行は `settle()` 一箇所に集約し、通常進行・非表示からの復帰・リロードが二重計上されないようにしました。オフラインは上限8時間・効率50%で、1秒を超える空白をオフライン扱いにします。
  - 複数タブは所有権方式です。先に開いていたタブが進行・保存を続け、後から開いたタブは停止して「このタブで続ける」ボタンを出します。
  - アップグレードは Lv100 が上限で、価格は現在 Lv から計算します。大きい値は K/M/B…や指数表記に短縮します。

## 設計書から足した挙動
- 星の収穫にも確認ダイアログを付けました。誤って押すと、累積がもっと貯まった場合より星が少なくなるためです。
- タブが非表示になったとき、所有権を手放します。前面に出したタブが進行するようにするためです。
- 保存キー `starsprout.v1.owner` を追加し、所有タブの管理に使っています。
