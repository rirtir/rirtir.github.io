# 黎明列車 ― アートディレクションガイド 2.4.0

- 制定: 2026-07-28
- 対象ビルド: 2.4.0
- 状態: 制作基準・正本

## 1. 品質基準

本作は「ブラウザで動くツール」ではなく、Steamで販売される短編～中編インディーゲームのストアページに静止画を並べても成立する作品として仕上げる。機能の存在だけでは完成としない。

主要画面は、UIを消しても場所・時間・物語上の温度が読み取れ、UIを重ねた状態でもスクリーンショット一枚から次の行動と危険が理解できること。汎用的な半透明カードの羅列、文字だけの状況説明、装飾目的の歯車、8bit風記号音、単色の丸と頭文字を完成表現として使わない。

各画面の完成判定は次の4層で行う。

1. 5秒: 世界観、現在地、主目的が分かる。
2. 20秒: 何を選べるか、何が代償か分かる。
3. 操作後: 入力に対して人物・列車・音・光が一体で応答する。
4. 長時間: 章ごとの景色と戦術の変化があり、同じ画面の色替えに感じない。

## 2. コアコンセプト

### 2.1 一文

「夜に沈んだ世界を、内部に朝を抱えた一両の列車が切り裂く、手描きの鉄道オペラ」。

### 2.2 固有の視覚言語

- 画面の主役は常に横へ走る列車。基本カメラは2D横視点で、車両断面と外の風景を同時に見せる。
- 絵は厚塗りの背景美術に、木版画のような強い輪郭と紙の粒子を重ねる。「綺麗なSF」より、煤、錆、濡れた鉄、曇った窓、縫い直した服を優先する。
- 暁核の光だけが高彩度の琥珀色。夜蝕は黒ではなく、紫紺の微粒子が星を逆向きに吸い込む現象として描く。
- 人物は写実とアニメの中間。実用服、年齢差、労働の跡を描き、ソーシャルゲーム風の過剰な装飾と均一な美形化を避ける。
- UIは「車掌の運行机」。黒鉄、煤けた骨色の紙、琥珀ガラス、赤い封蝋を素材にする。装飾は機能と結びつけ、理由のない歯車やネオン枠を置かない。

### 2.3 避ける表現

- ピクセルアート、8bit、レトロゲーム模倣
- 青一色の汎用SF HUD、サイバーパンクのネオン過多
- すべてを同じ角丸カードへ入れるWebアプリ的レイアウト
- AI画像特有の読めない文字、余分な手足、不連続な車輪・レール
- 背景へ直接日本語を描かせること。文字とUIはHTML/SVGで重ねる
- 蒸気機関＝歯車を無差別に貼る安易なスチームパンク

## 4. 画面とカメラ

### 4.1 タイトル

- 16:9のキービジュアルを全面表示。下1/3を走る黎明列車、右奥の灯台、上2/3に夜蝕。
- ロゴは画像へ焼き込まずHTMLで組む。明朝の縦画と細い欧文を組み、琥珀の水平線で区切る。
- メニューは左下の運行票として配置し、主ボタンだけ暁核色。設定等は小さな記号へ逃がさず読める文字にする。
- 「全7章・推定12時間・途中保存」の作品情報をタイトルで明示する。

### 4.2 導入・会話

- 背景美術を広く見せ、人物肖像は画面端から胸像で現れる。話者以外を暗くする。
- 地の文は画面下の「旅の記録」欄、台詞は肖像に接続した吹き出しではなく字幕板へ置く。
- 一画面の文字量を全角90字以内にし、環境変化→人物の反応→プレイヤーの目的の順で伝える。
- 初めて出る固有語は本文だけに頼らず、絵のフォーカスと短い用語札を併用する。

### 4.3 旅・路線選択

- 車掌の運行机を俯瞰した画面。背景に章の地図、中央に二本の路線票、上部に列車の横姿。
- 路線票を選ぶ前に、燃料計を光らせ「現在7 → 到着後5」のように結果を先に表示する。
- 各路線は「何が起きるか」「なぜ選ぶか」「代償」を一文と図記号で示す。単なる安全／危険ではなく、風景のサムネイルを持つ。
- 初回はクレハが燃料の意味を説明し、燃料計を実際に指し示すまで路線決定を許可しない。
- スマートフォン縦向きでは地図装飾を圧縮し、燃料予測、横並びの二枚の路線票、出発レバーを一画面で同時に見せる。情報を一枚ずつ巨大表示してページ送りや文書スクロールを要求しない。

### 4.4 戦闘

- 横長の背景の上に、6両までの列車断面を一続きで表示する。車輪と外景は常に横へ流れる。
- 3レーンは「屋根／車内／床下」ではなく、車両内の上段通路・中央通路・下段保守路として立体的に重ねる。
- 乗員は肖像と同じ配色の全身駒シルエット。敵は赤い丸ではなく、役割が輪郭で分かる切り絵風駒。
- 敵の攻撃予兆は赤い斜線と赤枠、プレイヤーの攻撃対象は青白い外枠と光で表示し、同じ赤へ二つの役割を持たせない。
- 選択中だけ照明が対象へ絞られ、移動は床灯、攻撃は射線、修理は火花でプレビューする。
- ダメージ時は車体の揺れ、火花、煤、短い数字、音を同期。勝利時は背景の夜が一段明るくなる。
- 画面下は人物肖像＋2～6個の大きな行動札。説明を右の独立パネルへ追いやらず、札の上で射程・AP・蒸気を読めるようにする。
- スマートフォンでは共有蒸気、勝利条件、ラウンド、予告、列車盤面、人物、全行動札を一画面の固定構図へ圧縮する。列車断面を縦へ引き延ばさず、縦長端末でも盤面高は310pxを上限とする。
- 行動の詳細は選択直後だけ煤けた骨色の説明札として盤面上へ重ね、約4秒で消す。恒常表示は右上メニューの索引へ分離し、戦闘画面を説明文で埋めない。
- 味方は乗員固有色の角形肖像・緑HP・水色の攻撃値・真鍮色のAP、敵は赤い異形フレーム・赤HP・赤い攻撃値で分類する。肖像そのものを見分けられない縮小率でも陣営と役割が分かること。
- スマートフォンでは装飾密度より文字の判読を優先する。勝利条件15px、人物名16px、行動13px、主要操作13～14pxを基準とし、攻撃札の補足へ消費APと実ダメージを併記する。行動説明札は本文14px未満へ縮めない。

### 4.5 整備

- 停車中の車庫を横から見た一枚絵。列車各部を直接クリックし、選択車両だけ作業灯が点く。
- 車両カード一覧を主画面にしない。耐久、設備、強化は選択車両の検査票として横へ開く。
- 初回損傷後、ガクが傷を指し、無料の練習修理を一度行わせてから部品消費を解禁する。

### 4.6 エピローグ

- 選んだ結末に対応した一枚絵を背景にし、各地域の後日談を路線沿いの写真として順に出す。
- 統計は最後に旅の記録として見せる。物語の余韻より先にスコア表を置かない。

## 6. 列車・敵・図記号

### 6.1 黎明列車

- 低い重心、六つの大車輪、黒鉄の装甲、中央に琥珀ガラスの暁核炉。
- 車両ごとに屋根形状と窓のリズムを変え、縮小表示でも見分けられる。
- 装飾ではなく補修跡、交換板、地域ごとの土産が旅の進行で増える。
- 車輪・連結器・レールは生成画像だけに依存せず、HTML/SVGの前景で構造を整える。

### 6.2 敵

- 通常敵8種は黒い切り絵＋一色の役割色。武器輪郭で近接、射撃、工作、支援を識別する。
- 章ボス7体は背景美術と同じ厚塗りで個別の大型肖像を用意する。
- 夜蝕由来の敵だけ輪郭の一部が粒子へほどけ、人物由来の敵と材質から区別する。

### 6.3 UIアイコン

- SVGをコード管理する。線幅2、角は小さく丸め、24pxで判別できること。
- 必須: 燃料、部品、医療、士気、AP、蒸気、耐久、障壁、移動、攻撃、修理、設備、射程、危険、記録。
- 絵文字、頭文字、Font Awesome等の外部アイコンに依存しない。

## 7. モーションと画面効果

- 通常時は背景3層を異速で流し、列車は1～2pxの低周波揺れ。UIは揺らさない。
- 画面遷移は黒フェードではなく、列車窓を横切る柱のワイプを基本とする。
- ダメージは100～180ms、勝利は1200ms。長い演出で操作を止めない。
- `prefers-reduced-motion` と設定「演出を減らす」ではパララックス、揺れ、粒子を停止する。
- 粒子はCanvas 1枚またはCSS疑似要素に限定し、DOMを無制限に増やさない。

## 8. 音響ガイド

### 8.1 方針

8bit風の単音、決定音としての高い電子ビープ、ゲームセンター的な勝利アルペジオを廃止する。音の中心は、鉄輪、連結器、蒸気、紙、革、遠い低音弦、ガラスの共鳴。

### 8.2 音の層

- BGM: タイトル、旅、通常戦、ボス戦、結末の5曲を場面に合わせて切り替える。低い車輪の周期、遠い風、擦弦、撥弦、ピアノ、木管、膜鳴りを使い、長時間でも旋律が前へ出すぎない密度にする。
- UI: 紙を送る音、木製レバー、金属の留め具。周波数を持つ音でも短いノイズと複数倍音を使い、単純な矩形波にしない。
- 戦闘: 攻撃種別ごとに金属衝撃、空気圧、低い車体振動を積む。修理は工具＋火花、回復は布＋ガラス。
- 場面遷移: 曲は約1.15秒でクロスフェードし、同じ場面の再描画では再スタートしない。曲頭・曲末はクリックノイズが出ないループ境界にする。
- 音量基準: BGM初期値40%、効果音70%。設定で個別に変更・保存でき、全音声を一括で切れる。連続音で疲れさせない。

### 8.3 制作・実装規則

- 外部素材は使わず、`tools/generate_audio.py` で本作専用のOggをオフライン生成する。
- 実行時の発振器や単純波形へ頼らず、完成済みのBGM 5曲・効果音12点を `assets/audio/` から再生する。
- 効果音の中心はノイズ励振、帯域フィルター、胴鳴り、複数の非整数倍音とする。音程だけで入力を区別しない。
- ブラウザの自動再生制限に従い、最初のポインターまたはキー入力後にBGMを開始する。
- 音源の生成手順、長さ、用途、検証結果は `ASSET_MANIFEST.md` を正本とする。

## 9. 操作ガイド契約

「説明を読めば遊べる」は不可。新しい判断・資源・操作は、使う直前に画面上の対象を示し、一つ行わせ、結果を見せてから自由操作へ渡す。

| 初出 | 操作前に伝えること | 必須体験 |
|---|---|---|
| 旅の目的 | 暁核を七夜で東端灯台へ運ぶ | 列車と灯台を一枚絵上で結ぶ |
| 燃料・路線 | 燃料は路線確定だけで減り、0でも詰まないが損傷する | 燃料7→5/6の予測表示を見て最初の路線を選ぶ |
| 乗員選択 | 人物を選ぶと行動札が開く | クレハを選択する |
| 敵の攻撃予兆 | 赤い斜線の区画が次の被害地点 | 狙われた区画から移動する |
| 攻撃 | 射程、装甲、予測ダメージ | 移動後に指定敵を攻撃する |
| ターン終了 | 残APは持ち越せず、終了後に予告どおり敵が動く | 退避と攻撃後、残APを表示したまま終了して敵行動を見る |
| 蒸気・固有技 | ラウンド開始で増え、固有技と設備が共有する | 3→5の増加を見た後、ガクで砲台車の主砲を使い5→3を確認する |
| 車両損傷・部品 | 戦闘後も残り、部品で直す | 初回だけ無料修理を行う |
| 編成・設備 | 車両上の乗員が設備を動かす | 砲台車上のガクを選び、主砲を一度使う |
| 医療・戦闘不能 | HPは持ち越し、医療品は戦闘外回復 | 最初の整備ガイドでHP・医療品・治療量を操作前に確認する |
| 強化・換装 | 不可逆な恒久選択 | 比較プレビュー後に確定する |

- チュートリアル中は関係のない操作を暗くするが、二回目以後は制限しない。
- ガイドは設定から再生可能。再開時は完了済み段階を保存する。
- 初回路線選択までに「燃料をなぜ使うか」「残量が何を意味するか」「安全／危険の違い」を必ず画面内で説明する。
- 操作を誤っても詰まない盤面とし、必要ならその一手だけAPを返す。

## 10. 画像資産規則

- 生成画像は `assets/art/` 配下へ用途別に保存し、外部通信なしで読み込む。
- 背景へ文字・UIを焼き込まない。ロゴ・数値・日本語はHTML/SVG。
- 画像は原則WebPへ変換し、デスクトップ背景は幅1920px以下、肖像は768px以下を目安にする。
- CSSで暗く隠す前提の低品質画像は採用しない。顔、手、車輪、レール、遠近の破綻を等倍で監査する。
- 同一人物の別絵が必要な場合は、採用済み肖像を参照画像として編集・派生する。
- 各生成プロンプト、採否、用途、ファイル名を `ASSET_MANIFEST.md` に残す。
