# MOSSLIGHT gameplay test plan (`tests/gameplay.js`)

## 実行方法

静的ブラウザESモジュール。Node不要。リポジトリ直下で `python -m http.server 8765` を起動し、`http://localhost:8765/Game/Mosslight/tests/` を開く。結果はページ表示と `window.testResult` に残る。ゲームのフォルダを基準とするESモジュールから直接呼ぶ場合:

```js
import { runGameTests } from './tests/gameplay.js';
const r = await runGameTests();            // {passed, failed, checks:[{name, ok, detail}], durations}
const one = await runGameTests({ only: 'forge altar' });   // シナリオ名で絞り込み（SCENARIOSも export）
```

- `file://` では ES module が読めないので、リポジトリ直下で `python -m http.server` などの静的サーバー経由で開く。
- 各シナリオは独立した `createWorld()` / `createState()` を作る（同一シナリオ内の派生ケースだけ世界を共有。世界は `createState` が毎回リセット）。
- シナリオが例外を投げると失敗チェック（`scenario threw` / `section: threw`）になり、残りは続行する。
- ステップ数は固定dt、乱数は固定シード。所要時間は返り値のdurationsに記録し、実行環境による違いを許容する。

## 方針

- ゲーム操作は公開関数（`step` / `interact` / `craft` / `place` / `remove` / `till` / `plant` / `harvest` / `restoreLight` / `bossRematch` / `damageEnemy` / `serialize` / `validateSave` / `createState`）で行う。
- `setLights` / `cleared` / `questdone` / `progress.*` の直接書き換えは一切しない。進行は祭壇・皿・ボス撃破・拾得を通して満たす。
- フィクスチャとして許すもの: `addItem`（素材の付与）、`teleport`、`setClock`、`quiet()`（ランダム敵の出現タイマーを止める）、ボス戦の `state.rng` 固定（最初の攻撃を蔓叩きに固定）、`combat.playerDeath` の直接呼び出し。
- 採集の初期導線は `step` の実入力（マウス狙い＋行動ボタン）。

## グラインド回避のため省いた操作（フィクスチャで代替）

- 銅/翠鉄の採掘〜精錬、苔灯油・シチューの調理、光苔結晶の大半の探索: `addItem` で付与（レシピ自体は別シナリオで実際に `craft`）。結晶1個だけは実際に小部屋で採取。
- 3軒以上の家・生活目標の資材（床/壁/灯籠/石畳60）: 付与して公開APIで設置。
- 敵の戦闘ダメージ蓄積: ボスは `damageEnemy` を剣の実ダメージ（装備から計算）で連打。ボスの攻撃回避は別の短い試験で実時間ステップ。
- 移動: `teleport`。

## 既知の制限

- 最初のテストは静的読解で作成し、その後実ブラウザで実行して実装とフィクスチャを修正した。将来の地形やルール変更で前提が崩れた場合は、detailから実装の欠陥とフィクスチャの誤りを区別する。
- 家のサイトは安全圏内の空き地を探す（草・枝などの素手採集物は `interact` で片付ける）。見つからなければシナリオが例外で失敗する。
- このgameplay.jsは描画・音・UI・タッチ・タブ非表示の停止を直接検証しない。描画と入力は別のブラウザ試験で確認する。
- 夜間のNPC就寝位置、敵AIの細部、確率ドロップ（苗30%、灯麦の種10%）は検証しない。

## 検証で修正した問題

- 0以下・非有限の保存個数からアイテムを作らず、無効なエントリを除外する。
- 家の灯りは燭台または石の灯籠とし、たいまつだけでは成立させない。
- 採掘できない遺跡壁・封印へのinteractを例外なしで拒否する。
- 読込直後に住人を復元する。
- 制作では材料消費後の空き枠を評価し、失敗時の素材消費をゼロに保つ。
- 灯皿の点灯に炉の灯・苔の灯の復旧を要求する。
- 建築士の生産間隔を、配列のeveryメソッドと混同しない。
- 進行処理から複数のイベントを送れるようにし、終幕・保存通知を欠落させない。
- 成熟した畑を取り壊した場合も収穫物を返す。未熟時は種1個、満杯時は余剰を地面へ返す。

フィクスチャ側では、制作前の石の数、材料消費で枠が空く満杯バッグ、ボスの報酬位置へ移動して拾う処理を修正した。進行フラグの直接操作でテストを通す方法は使っていない。

上記の問題は修正済み。保存の取消で共有世界が巻き戻る問題も、復元を独立した世界で行い、承認後だけ世界を切り替える修正を適用した。

追加の `sustainability.js` は、畑の取り壊し、切り株への苗植えの実入力・フォーカス名・無消費の拒否・60秒での再生・保存復元・アイテム非複製を検証する。`tests/index.html` は元の進行テストと合算する。キャンペーンの報酬試験は、唯一の噴水が地面で時間消滅しないこと、復元後の保持、通常の箱への移動、死亡後の非複製を検証する。

実ブラウザの保存耐久性は `python Game/Mosslight/tests/browser_save_regression.py` で実行する。有効ファイルとバックアップの確認中・取消後、壊れたファイル、承認後の未採掘／採掘済み世界の正しい復元、リロード後の継続、世界参照の一致を検証する。

## アセットと実ブラウザ

```text
python Game/Mosslight/art/rebuild.py --check-only
python Game/Mosslight/tests/check_assets.py
python Game/Mosslight/tests/browser_lighting.py
python Game/Mosslight/tests/browser_smoke.py
python Game/Mosslight/tests/browser_save_regression.py
```

- rebuildのcheck-onlyは保存ソース・フレーム順・pivot・atlas配置を確認し、画像を書き出さない。
- check_assets.pyはアトラスの範囲、空フレーム、パレット、manifestとの整合とポーズ間の画素差を検証する。画素差だけで歩行の自然さを判定しない。
- browser_smoke.pyはChromeとPython Playwrightを使う。実キーでの移動、バッグ・制作・建築・マップ・日誌、画面を開いている間の停止、制作、保存・書き出し・正常/不正ファイル読み込み・再開を検証する。390×844および844×390でホットバー、横幅、実タッチの移動・停止・回避・バッグを確認する。
- ブラウザ試験の結果・画面・書き出したセーブはGit対象外のtests/output/に保存する。

照明の実ブラウザ試験は `python Game/Mosslight/tests/browser_lighting.py`。光源の左右移動とnormal応答、夜、太陽・局所のheight影、壁遮蔽、粗さ、法線Yの向きと上下反転なし、GL context lostからの復帰、PC/touchでの実GLとfallbackを検証する。

照明の計測値の範囲: RAF中央値約16.7msは、headless Chromeでの同一PCのPCとモバイルエミュレーションの値で、物理端末の速度保証ではない。`ms.gl` はCPU側の発行時間で、GPU時間ではない。

昼夜、家の内外、地下、ボス戦、動作中の造形・接地・予兆の読みやすさは実画面で評価する。合格数からフルプレイの所要時間、音の品質、Steam作品とのビジュアル同等性は保証しない。長時間の手動プレイや確率ドロップの統計検証はこのテストに含めていない。
