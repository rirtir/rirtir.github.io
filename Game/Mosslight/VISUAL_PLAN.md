# VISUAL_PLAN — 見た目改善設計（Claude Opus / 2026-10-05）

比較対象: `.review/current-title.png`, `.review/current-play.png` と公式参照画面（Romestead / Core Keeper。分析専用。素材には使わない）。
前提: 木と主人公は更新済み。その他は差し替え途中。照明・粒子で原画の弱さを隠す処方はしない。

区分: **[原画]** = Codexがimagegen原画→PixelWorkbenchで新規素材化 / **[描画]** = renderer.jsの描き方 / **[配置]** = ワールド生成・置き方のルール

## 全体の診断（画像から）
- 木だけが参照並みで、地面・道・小物が旧品質のまま。木以外の画素密度・パレット・輪郭線の有無が揃っていないため、素材が貼り合わせに見える。
- 地面は「32px正方形＋ノコギリ歯の縁」が全面に見える。道・暗い草・空き地のどれも直角の階段形で、参照のような丸みと層のある地形の塊がない。
- 物が画面全体に同じ間隔でばら撒かれ（丸い茂み・灰色の石・短い丸太・花）、目立つ物が多すぎるのに、地面の細部は足りない。参照は逆で、目立つ物は少なく群れていて、地面には目立たない細部が多い。
- 2枚のキャプチャで岩・茂み・主人公の絵が違う（タイトル=新、プレイ=旧）。

## 優先度順の処方（19項目）

### 1. 地形境界をデュアルグリッド16通りにする ［原画＋描画］最優先
- 問題: `grassedger` を4辺に回転して貼るだけなので、角の処理がなく、縁は一様な三角のノコギリ歯。道・広場・暗い草の区画がすべて32pxの階段形に見える（プレイ画面の中央広場や右上の暗い草の四角）。
- 原画: 境界の組（`grass/dirt`、`grass/darkgrass`、`grass/sand`、`sand/water`、`dirt/path`、`cave/moss`）ごとに、4角の所属で決まる16パターンの32x32タイル（`edge_<上側>_<下側>_0..15`）を作る。縁は丸い張り出し・草の房・土の小石が混ざる不規則な2〜6px幅の帯にして、三角の反復は禁止。1つのimagegen原画から「全面A・全面B・凸角・凹角・直線・対角」を描かせて切り出す。
- 描画: 表示タイルを半マスずらし（`tx*32-16`）、4隅のterrainで0..15を引く。地形には優先順（水<砂<土/道<草<暗い草）を付け、高い側を上に重ねる。`FRINGE`/`fringeSprite` は廃止する。
- 受入: プレイ画面を2倍に拡大しても、32px周期の直角と三角の歯が見えない。凹角・凸角・1マス幅の道の端がすべて途切れずに繋がる。

### 2. タイル単位の陰影塗りを廃止する ［描画］
- 問題: `info.calm` と `map.shade` でマスごとに `fillRect` しているため、明暗の正方形ブロックが市松状に見える（タイトル画面の左側、プレイ画面の右上）。
- 処方: マスごとの塗りを削除する。明暗の差は3と1の「草の種類の違い」として、原画タイルとデュアルグリッド境界で表す。
- 受入: 同じ地形の中に、32pxの正方形で区切られた色の差が1つもない。

### 3. 地面に大きなパッチを作る ［原画＋配置］
- 問題: 草は4種類のタイルの細かい模様の繰り返しだけで、画面全体が同じ濃い緑の一枚に見える。参照の草は、明るい草地・基本の草・暗い丈の高い草が数マス単位の有機的な塊で重なっている。
- 原画: `meadow0..3`（明るい草地・クローバー）、`tallgrass0..3`（暗く穂の立った草。下端3pxの穂が隣のマスへはみ出す）、`worn0..3`（踏まれて土が見える草）。いずれも色相をずらした3〜4階調で、基本の草と明度差8〜12%以内。
- 配置: 低周波ノイズ（周期6〜12マス）で meadow / grass / tallgrass を割り当てる。道と広場の周囲1〜2マスは worn にする。
- 受入: 1画面（約20x11マス）に、大きさの違う草の塊が3種類以上、各4マス以上の塊で見える。同じ模様が横に3マス以上続かない。

### 4. 道と広場の形を直す ［配置］
- 問題: 道は幅1マスの直線と直角の曲がりだけ。野営地の広場は四角を寄せ集めた形。
- 処方: 主要な道は幅2〜3マスにし、ノイズで幅を±1揺らして、曲がり角は斜めに2段以上かけて曲げる。広場は半径3〜4マスの円か楕円に、ノイズで縁を崩した形。道の中心線沿いに `path`（踏み固めた土）、縁に `dirt` を置き、1の境界で2段に移り変わらせる。
- 受入: 直角の曲がりがない。広場の外形に、3マス以上続く直線の縁がない。

### 5. 水辺と岸を作り直す ［原画＋描画］
- 問題: 岸は `shore` の帯を回転させるだけで、角は4pxの単色の四角で埋めている。水面と陸の高さの差が見えない。
- 原画: デュアルグリッド16通りの `edge_sand_water`。陸側の縁の下に2〜3pxの暗い土の側面と、水面へ落ちる影の帯を描き込む。浅瀬の泡の線、睡蓮、葦の根元を、16x16のデカール4種として作る。`water0..3` は、明るい揺らぎの線が並ぶだけの模様をやめて、深さで2段の色にする。
- 描画: 角を四角で埋める処理（`drawShore` の対角の `fillRect`）を削除する。
- 受入: 岸のどの角にも単色の四角がない。陸の縁の下に、側面の暗い帯が途切れずに一周する。

### 6. 高低差（段差・崖）を導入する ［原画＋配置］
- 問題: 地表が完全な平面で、画面に大きな構図がない。参照は段差の縁と、その向こうの暗い塊で画面を区切っている。
- 原画: `cliff_top`（上面の縁、デュアルグリッド16通り）と `cliff_face0..3`（32x32の前面。土の層・根・苔の垂れ）。前面の下端に、接地する暗い線を描く。
- 配置: 地表マップの外周と、地域の境界に、高さ1段の台地を2〜4か所置く。前面は南向きだけ描き、北・東・西は上面の縁だけにする。
- 受入: 初期地点から1画面以内に、長さ6マス以上の段差の前面が1本見える。

### 7. 森の外周を樹冠の塊にする ［配置＋原画］
- 問題: 更新済みの木が1本ずつ離れて立ち、画面の端は「木がたくさんある草地」に見える。境界の壁として機能していない。
- 配置: 外周と森の地域では、木の間隔を0.6〜0.8マスにして樹冠を重ね、奥の列ほど暗い変種を使う。手前の列だけ幹を見せる。
- 原画: `canopy_mass` を、デュアルグリッド16通りの暗い樹冠の地面タイルとして作る。木の奥の列を、この地面で埋めるため。
- 受入: 外周は隙間なく樹冠で塞がり、奥の草地が見えない。その手前の列の木は、1本ずつ輪郭が読める。

### 8. 小物の密度と群れ方のルール ［配置］
- 問題: 丸い茂み・灰色の石・短い丸太・花が、画面全体に同じ間隔で散らばっている。目立つ物が多すぎて、どこを見ればいいか分からない。
- 処方: 目立つ物（茂み・岩・丸太・花の塊）は、1画面に12〜18個までにする。必ず2〜5個の群れにして（例: 岩1つ＋小石2つ＋シダ1つ）、群れの間に空いた地面を残す。丸太は、木の近くか野営地にだけ置く。同じ種類・同じ向きの物が、隣り合って3つ以上並ばないようにする。
- 受入: プレイ画面の目立つ物が18個以下。単独で置かれた物が3割以下。

### 9. 目立たない地面の細部を原画で足す ［原画＋描画］
- 問題: 地面の細かい模様が、白っぽい「ハの字」の刻みだけ。
- 原画: 16x16のデカールを10〜14種作る（草の房3、落ち葉2、小石2、クローバー、苔の染み、根、土の割れ、きのこの輪）。地面からの明度差は±10%以内、輪郭線なし。
- 描画: `drawDeco` で、マスごとに0〜2個のデカールを地形の種類別の表から選んで置く。現在のbush/flowerを半分に縮めて代用する処理は廃止する。
- 受入: 何も置いていない草地のどのマスにも、近づくと細部があり、遠目には一枚の地面として沈んで見える。

### 10. 縮尺の基準表を決め、縮小の代用を禁止する ［原画＋描画］
- 問題: 物ごとに縮尺がばらばら（看板が主人公より大きい、宝箱と樽が主人公と同じ高さ、すべての岩がほぼ同じ大きさ）。`half`（実行時の2x2縮小）で、ドットがつぶれて濁る。
- 基準（見えている画素の大きさ。主人公は高さ30〜34px）: 小石 6〜10 / 岩 14〜20 / 大岩 28〜40 / 宝箱 22x18 / 樽 16x20 / 看板 20x24 / 焚き火 22x16 / 丸太 26x10 / 茂み 18〜26 / 作業台 40x28 / テーブル 2x1マス / 椅子 14x18 / ベッド 1x2マス / 苗木 12x18。
- 処方: `import_assets.py` は、名前ごとに目標の外形サイズを受け取り、その大きさで減色・切り出しをする（画素密度を1:1に揃える）。本番の描画名では、`half` と `buildVariant` の縮小を使わない。
- 受入: 最終描画名で `half` の使用が0件。主人公の隣に置いて、上の表から±15%以内に収まる。

### 11. パレットと輪郭線を全シートで統一する ［原画］
- 問題: シートごとに64色で減色しているため、木・岩・道具・地面の色の系統がばらばら。木には暗い輪郭線があり、旧来の石や丸太にはない。
- 処方: 全シートで共通の48〜56色のパレットを1つ定め、`import_image` の減色先として固定する。輪郭線のルール: 物と人物は、黒ではなく色相をずらした暗い色の1px線を外周に付ける。地面タイルとデカールには付けない。光の向きは左上に統一し、右下の面を1〜2段暗くする。
- 受入: 全アトラスの色数の合計が、共通パレットの色数を超えない。物と人物の外周に、輪郭線の抜けがない。

### 12. 建築の壁・床・屋根の原画を作る ［原画＋描画］
- 問題: 契約上は、壁=`wall` の物を1マスずつ並べて、屋根=`roof0..8` を重ねる。参照（Core Keeper）の壁は「上面の帯＋前面の高さ」があり、床に模様の継ぎ目がある。今の作りでは、箱を並べただけになる。
- 原画: `wall_top_<素材>_0..15`（デュアルグリッド16通り）と `wall_face_<素材>0..3`（32x24。板張り／石積み。窓・扉の変種）、`floor_<素材>0..3`（板の継ぎ目が隣のマスと揃う）、`roof` は軒の出が8px、切妻の前面が見える9分割（棟・軒・角）。素材は木と石の2系統。
- 描画: 壁は、上面をデュアルグリッドで、前面を南に面した壁の下にだけ描く。屋根は、壁の外周から上8px・左右4px大きく描く。
- 受入: 3x3以上の家の外観で、壁の前面・上面・屋根の軒が途切れずに繋がる。室内の床の継ぎ目が、隣のマスとずれない。

### 13. 家具をマスの占有に合わせて描き、室内を密にする ［原画＋配置］
- 問題: 家具が96x96の汎用の枠の中心に描かれ、マスに対する大きさと接地位置がまちまち。
- 原画: 家具は、占有するマス（1x1 / 2x1 / 1x2）の床にちょうど接地する形で描き、背の高い物（棚・炉）は、上に最大1マスはみ出す。壁際に置く物（棚・額・窓辺の鉢）を4種追加する。
- 配置: NPCの家の自動配置では、壁際に家具を寄せて、中央に通路を1マス残す。1部屋に家具を4〜7個置く。
- 受入: どの家具も、接地線がマスの境界から±2px以内。室内のキャプチャで、壁際の8割以上が家具で埋まる。

### 14. 主人公のアニメーションを手描きのキーポーズにする ［原画］
- 問題: `animate_hero.py` は、待機の1枚を6つの部品に切り、2px上下にずらすだけ。歩きは足が上下に跳ねるだけで、前に出ない。回避は頭が下がるだけ。攻撃は腕だけが動く。部品の境目に、すき間や二重線が出やすい。
- 処方: 方向ごと（下・上・右。左は右の反転＋道具を持ち替え）に、imagegenでキーポーズの原画を作る。歩き6枚（接地・通過）、攻撃4枚（予備動作・振り・追従・戻り）、回避4枚（しゃがみ・丸まり・転がり・起き上がり）、待機2枚。部品をずらす方式は、待機の呼吸にだけ残す。
- 受入: 歩きの各フレームで、輪郭が前のフレームと15%以上違う。部品のすき間が0。左右の歩きで、足が交互に前へ出ているのが読める。

### 15. 道具と攻撃を手に持たせて描く ［原画＋描画］
- 問題: UI用の24pxアイコンを、手の近くに貼っているだけ。参照の剣は細く、振った軌跡が絵の中にある。
- 原画: 手持ち用の道具（斧・つるはし・剣×素材3段階）を16x16で、角度3段階（構え・振り・振り切り）ずつ作る。剣の振りの残像（3フレーム）を、方向別に作る。
- 描画: 攻撃フレームの番号に合わせて、手の位置の表から手持ち用の道具の絵を選ぶ。`SWING_POS` とアイコンの流用は廃止する。
- 受入: 戦闘中の画面に、UIのアイコンが一切映らない。

### 16. NPCと敵に方向と状態を持たせる ［原画］
- 問題: NPCと敵は0..3の4枚の繰り返しだけで、向きも歩きもない。料理番は、庭師の色を変えただけ。
- 処方: NPCは、下・右（反転で左）・上の歩き4枚ずつ＋待機2枚。料理番は、エプロン・帽子の形を変えた別の原画にする（色替えは禁止）。敵は、移動4・予備動作2・被弾1・消滅3の枚数にする。予備動作は、姿勢で読めるようにする（縮む・身を起こす・発光部を開く）。
- 受入: NPCの歩く向きと、絵の向きが常に一致する。敵の攻撃の0.3秒以上前に、予備動作の姿勢が出る。

### 17. 地下の壁をオートタイル化し、鉱石を壁の中に入れる ［原画＋描画］
- 問題: 地下の壁は、`rock` の物を1マスずつ置いて暗く塗っているだけで、同じ丸い岩が並ぶ。参照は、壁の上面＋前面が連続する塊で、鉱石は壁の面に埋まって見える。
- 原画: `cavewall_top_0..15`（デュアルグリッド16通り）と `cavewall_face0..3`（32x20。層・亀裂）、鉱石入りの前面 `cavewall_face_copper/iron/crystal`、苔の洞窟用の色違いの1組。床 `cave0..3` に、ひび・水たまり・砂利の変種を足す。
- 描画: 採掘できる壁も、同じタイルで描く。鉱石は前面の変種で表し、採掘中は前面の上にひびのデカールを3段階で重ねる。
- 受入: 地下で、同じ岩の物の反復が見えない。銅・鉄・結晶が、照明なしの昼の明るさで、壁の色だけで区別できる。

### 18. ボスは大型専用の原画と、アリーナの床を作る ［原画＋描画］
- 問題: `boss_*_large` という名前を実行時に引いているが、契約にある名前は32x48の `boss_moss0..3` だけで、3倍に拡大する前提。拡大すると画素密度が崩れる。
- 原画: ボスごとに128x128（pivot 64,112）で、待機4・予備動作3・攻撃4・被弾1・倒れ6の枚数を描く。苔のボスは本体＋蔓の腕2本、結晶のボスは本体＋周回する結晶片を、別部品として描く。アリーナの床デカール（根の網・結晶の筋・ひび割れの輪）を8〜10種、地面タイルとして作る。
- 描画: 拡大表示を禁止する。部品は本体の基準点からの位置の表で重ねる。
- 受入: 拡大した画素が0。ボスの外形が主人公の3.5〜4倍の高さになる。アリーナの床だけで、ボスの部屋だと分かる。

### 19. UIをドット絵の枠とロゴにする ［原画＋CSS］
- 問題: タイトルのロゴは、グラデーションと光彩のサンセリフ体の文字。メニューは角の丸い半透明のWeb風のボタンで、背景のドット絵と画風が合っていない。説明文が画面中央の焚き火の上に重なる。
- 原画: ドット絵のロゴ（苔と灯をあしらった、約240x56のビットマップ。整数倍で表示）、9分割の枠（パネル・ボタンの通常／選択／無効・ホットバーの枠・ツールチップ）を、共通パレットで作る。
- CSS: ゲームCSSで `border-image` の9分割、`image-rendering: pixelated`、整数倍の拡大にする。`border-radius`・`box-shadow` のぼかし・`text-shadow` の光彩はやめる。タイトルの説明文は、左下のメニュー側に寄せて、焚き火と主人公を隠さない。日本語の本文は、既存のフォントのまま、くっきり（光彩なし・1px暗い縁取りまで）にする。
- 受入: タイトルとHUDに、角丸・ぼかしの影・グラデーションの文字が1つもない。タイトル画面で、焚き火と主人公の上に文字が重ならない。

## 検収キャプチャの条件
- タイトルとプレイは、同じビルド・同じシードで撮る（今は岩・茂み・主人公の絵が、2枚で違う）。
- 地表の昼・水辺・家の内外・地下の採掘面・ボス戦の5場面を、等倍と2倍拡大で撮り、各項目の受入条件を、その画像で確認する。
- アセットの欠けを表す仮の四角（`placeholder`）が、0件であること（`assets.missing` が空）。
