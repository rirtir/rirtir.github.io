### 1.2 木
- `assets/flora` の4本（oak / oak2 / pine / amber_tree）は、**すべて幹が根元から斜めに傾いている**。同じ傾きの4本が繰り返されるため、森全体が同じ方向へ流れて見える。参照の森は、まっすぐ立つ幹と、まれな曲がりで構成されている。
- アルベドに左上光が描き込まれている（樹冠の左上が黄緑、右下が暗い）。そのうえ `build_normal_maps.py` の flora は `23 + dist*0.65`。4近傍の距離変換＝マンハッタン距離なので、法線は**ピラミッド状の4面**になる（`flora/normal.png` で、樹冠全体に対角の稜線が1本ある）。葉の塊ごとの丸みがない。
- 補正値 gain は「描き込まれた光を法線で弱める」だけで、昼の太陽の向きが変わると矛盾が出る。

### 1.3 材質・法線
- 地面の高さは `build_normal_maps.py` で**パレット記号ごと**に決まる（`roles` の表）。つまり明るい色＝高いの写像で、「色の明度＝形」を言い換えたにすぎない。
- 人物の高さは y の帯（18 / 11 / 3）。腰と胸の高さで段差ができ、`explorer/normal.png` に水平の赤緑の帯が出る。
- HEIGHT パレットは 8段×粗さ2×gain4 で64色を使い切り、32px より高い物を表せない（木の樹冠は実際は 40〜60px 相当）。

### 1.4 光と時計（数値で確認）
- 表示時刻は `ui.js`: `hour = (6 + tod/600*24) % 24`。`BALANCE.day` は dawn 0–60（06:00–08:24）、day 60–390（〜21:36）、dusk 390–450（**21:36–24:00**）、night 450–600（00:00–06:00）。ユーザーの指摘どおり、夕焼けが22時前後にずれている。
- 夜は `nightLight 0.35`。GL の sky は `lerp(0.06, 0.55, day)` で linear 0.06（sRGB で約28%）。2D fallback の暗幕は alpha 上限 0.86、夜で 0.52。`.review/latest-night.png`（2:20）は、灯のない草地でも中間の緑がはっきり見える。「23時はほぼ黒」と全く違う。
- 太陽は `lighting.js` の定数 `SUN = (-0.5, 0.5, 0.7)` で終日固定。影の向きと長さが時刻と無関係。夜でも主人公に半径2タイルの光が付き、灯の価値が下がる。
- 2D の楕円の接地影（`drawShadows`）は color buffer に直接描かれ、GL の高さ影と二重になる。向きも時刻と無関係。

### 1.5 地面
- `drawTerrain` は dual-grid の4隅マスク16種（`edge_{mat}_{1..15}`）を32pxセルに貼る。境界は16px単位の階段＋ギザギザ線で、ブロック形が見える。
- `edges/contact.png` では、dirt / path / sand の縁に**明るいクリーム色の1px線**、grass_sand に黄色の線が描かれている。これが「白い線」。水辺の泡 `#c8e0d6` の1px列も同類。
- 地面の模様は32px周期で繰り返す。細かな散らし（小石・落ち葉・草の葉）がない。代わりに、拾える物と同じ大きさの装飾（`drawDeco` の bush / flower / fern 縮小）が置かれ、拾える物と区別できない。

### 1.6 当たり判定
- 構造物: `resolveCollisions` は円を `ty*32+16`（タイル中心）に置く。`drawStructure` の足元は `ty*32+28`。**焚き火・灯籠・たいまつ・鍋の当たりが、見た目の根元より12px北にずれている**。
- 主人公: `P.radius 10`（幅20px）。見た目の靴の幅は約12px。木（r10）とは中心間20pxで止まり、樹皮と靴のあいだに約10pxの見えない壁がある。
- 木: 当たりは pivot (48,80) の円だが、幹が傾いているため、根元の中心が pivot から数px外れる（正確な値は §7 の計測で出す）。フォーカス矩形は既定の 28×36 で、傾いた幹の上部と合わない。
- 反転を使う場合、根元のずれ dx も反転させる契約がない。

### 1.7 以前の検収が通ってしまった理由
機械テスト（フレーム順・pivot・byte 一致・glErrors）を合格の根拠にし、原寸の実画面を参照画像と同じ倍率で横に並べて比べていなかった。本書では §10 の**画像による関門**を先に置き、機械テストは退行防止にだけ使う。

### 2.2 コンセプト3案（すべて独自。参照の人物の部品を写さない）
**A. 灯守りの見習い（推奨）**
苔緑の短いフード付き肩掛け（フードの先が後ろへ尖る）、黄土色の襟巻、生成りの袖をまくった上衣、濃紺のズボン、膝下までの革靴。腰の右に**真鍮の小さな手提げ灯**。栗色の髪は、横に流した前髪と、背中に下がる1本の三つ編み。物語（灯を取り戻す）と直結し、手提げ灯の核は発光画素になる（夜の主人公の目印。§5.6）。
シルエットの識別点: フードの尖り、三つ編み、肩掛けの裾の広がり、腰の灯。

**B. 苔渡りの斥候**
片側だけの樹皮色の革の肩当て、苔で染めた青緑の胴着、生成りの巻き布の腕、量の多い銅色のくせ毛と、葉の髪留め。片側の短い外套。

**C. 苔地の薬草摘み**（旧 C の鍛冶は、暖色が土の道と同じ値になるため差し替え）
つばの広い葦編みの帽子（頭の塊を横へ広げる。帽子のつばの下に顔の影）、生成りの短い外套、青緑のスカーフ、肩から斜めに下げた籠、黒髪のおかっぱ、苔色の脚絆。
識別点: 帽子の横長のシルエット、背中の籠（back で読める）。弱点: 帽子で顔の上半分が暗くなり、目の読みやすさが下がる。

### 2.5 形の層（法線・高さの元）
各部位を Workbench の part として、アルベドの rows と同寸の **shape rows** を持つ。shape の各記号は、プリミティブ表の1項目を指す:

## 3. アニメーションと解剖の一貫性

### 3.1 リグ（正本 `art/hero3/rig.json`）
フレームごとに関節の座標（pivot 基準）を持つ: `head, neck, shoulderL/R, elbowL/R, handL/R, hip, kneeL/R, footL/R, grip`。組立スクリプトが part を関節へ置く。全方向で同じ骨の長さを使う（上腕4・前腕5・腿5・脛5）。テストで骨の長さが ±1px 以内を確認する。

### 3.2 動作（名前と枚数は現行契約のまま）
- idle0..1: 呼吸。胴が1px上下し、頭も1px遅れて動く。三つ編みは1px揺れる。
- walk0..3: 接地 → 通過 → 接地 → 通過。接地の靴底は y57。通過で頭が1px上がる。腕は脚と逆に振る（手の移動 3px）。肩掛けの裾は1フレーム遅れる。
- attack0..2: 予備動作（体を引き、重心を後ろへ） → 打撃（腕を伸ばし、肩掛けがなびく） → 戻り。`grip` に道具を重ねる。打撃のフレームに1フレームの残像（smear）を許す。
- roll0..2: 前屈で手を地面へ → 丸まり（髪・肩掛け・靴の色が読める球。単色の球にしない） → 起き上がり。
- 将来 walk を6枚へ増やすときは `heroFrameName` の `walkT/15 % 4` を変える。今回は行わない。

### 3.3 4方向と反転
- down / up / right は別々に描く。left は **right の part を左右反転して組み直した版**（ゲーム内の反転ではなく、資産生成時の反転）。shape も反転するため、法線の Nx は生成時に自然に反転する。
- 非対称の部品（腰の灯）は、left では「奥側」の層へ移し、胴の後ろに描く。三つ編みは背中の中央なので反転しても同じ。
- 道具: `GRIP_POS` を rig の `grip` から書き出した値へ置き換える（renderer の定数とテストで一致を確認）。道具の left 反転は既存の `flip`（`flipNormalX` 付き）を使い続ける。

### 3.4 アニメーションの関門（G2）
4方向×14枚のシートと、GIF を1×・3×で出す。実際の地面の上で、昼・17:30・夜（灯あり）の3通り。確認項目: 接地のずれ0px、骨の長さ、髪と肩掛けの追従、攻撃の予備動作がはっきり見えること、回避中も服の色の区分が読めること。

## 4. 木・材質: 中立なアルベドと、形から作る法線・高さ

### 4.1 原則
1. **アルベドに方向のある光を描かない**。上・左・右の縁取りの光、片側だけの明るい面を禁止する。許すのは、材質の色差（葉の塊ごとの暖色と寒色、樹皮の苔）、**形の凹みによる遮蔽**（葉の塊の間、根の付け根、服の折り目）、輪郭の線。
2. **明るい色＝高い ではない**。高さと法線は形のプリミティブから作り、色の値から作らない。
3. **白っぽく褪せた色＝中立 ではない**。中立とは「光を含まない」意味で、彩度と固有の明度は保つ。材質ごとの目安（L*）: 草 38〜50、土 34〜46、樹皮 24〜36、葉 34〜52、岩 40〜58、肌 70〜80。最大でも 85（白は使わない）。
4. 反転は解禁する。法線は `flipNormalX` で Nx を反転し、高さは位置だけ反転する（renderer に実装済み）。

### 4.2 形の層（全資産で共通の作り方）
- 新規ソース `art/shapes/{sheet}.json`: フレームごとに `{primitives:[...], rows:[...]}`。rows は1文字＝プリミティブ番号、`.` は透明。
- プリミティブの種類: `ellipsoid(cx,cy,rx,ry,base,top)`、`cylinder(polyline,radius,base,top)`、`plane(nx,ny,h0)`、`blob(cx,cy,r,lumps,seed)`（葉の塊）、`groove(polyline,depth)`（溝・折り目の負の高さ）。
- `build_normal_maps.py` に分岐を足す: shape がある frame は、プリミティブから高さ（絶対px）と法線を解析的に求める。塊の境界は法線が不連続のまま残り、それが葉や房の稜線として読める。shape がない frame は、従来の方法（段階移行用）。
- HEIGHT パレットを変える: gain を廃止し（B=128 固定）、高さ 0〜62 を 2px 刻み×粗さ2 = 64色。shader の gain の clamp は残すが、新しい資産は常に 1.0。
- 検証用の `art/lightbox.py`（新規）: アルベド・法線・高さを、06:30・09:00・12:00・15:00・17:30・月光の6条件と、その左右反転で照らした板を出す。shader と同じ式（§5.3）を Python で再現する。

### 4.3 木の新しい構成（`flora` を描き直す。名前は維持し、変種を増やす）
| 名前 | 形 | 幹 |
|---|---|---|

### 4.5 中立なアルベドへの描き直しの範囲（全主要資産。3つだけではない）

## 5. 実行時の太陽・空・影・暗さ

### 5.1 時計
`hour = (6 + (clock mod 600) / 25) mod 24`（ui.js と同じ式）。1時間 = 25秒。新しい純粋モジュール `sky.js` の `hourOf(clock)` で計算し、テストで ui.js の表示と一致を確認する。
**gameplay の夜を見た目の暗さに合わせる**（ずれを残さない）。夜の長さ（約170 tick ≒ 6.8時間）と出現の総量は保ち、進行の難度を変えない。
| 項目 | 現在 | 新しい値（tod = clock mod 600） |
|---|---|---|
| 夜の敵（`combat.js` isNight） | 00:00〜06:48 | **21:00〜04:00（tod 375〜550、175 tick）**＝§5.5 の「ほぼ黒」の時間と一致。湧く間隔は変えない（長さがほぼ同じため） |
| 睡眠できる時刻 | 21:36〜 | **19:00〜（tod 325〜）**。起床は従来どおり 06:00 |
| `BALANCE.day` の区分 | dawn 0–60 / day 60–390 / dusk 390–450 / night 450–600 | dawn 0–50（06:00–08:00）/ day 50–275（〜17:00）/ dusk 275–375（17:00–21:00）/ night 375–550 / 夜明け前 550–600 は dawn 側の「predawn」 |
| `main.js` の夜の BGM | 区分に従う | 19:00〜05:00 |
- 区分の名前を参照する他の処理（UI の色、住人の帰宅など）は、Sonnet が P3 で `grep` して同じ表に合わせる。セーブの `clock` はそのまま読める（値の意味は不変）。
- テスト: 新しい isNight の窓と §5.5 の ≤ 8 の窓が一致すること、1日の出現数の期待値が変更前の ±10% 以内。

### 5.2 太陽と月の向き
- 仰角: 06:00〜18:00 で `e = asin(sin 62° · sin(π(h−6)/12))`。それ以外は負（太陽は無効）。
- 方位: 画面座標（x 右、y 下 = 南）で、太陽の方向 `d = normalize((sin φ, cos φ) + (0, 0.35))`、`φ = π(12−h)/12`。06時は東、12時は南（画面下）、18時は西。南へ少し寄せ、正面の面がいつも少し照らされるようにする。
- shader の `uSunDir = (cos e·dx, −cos e·dy, sin e)`（既存の uniform。lighting.js の定数 `SUN` を廃止して毎フレーム渡す）。
- 月: 20:00〜04:30 に、方向 `(−0.3, 1)`・仰角 35° の青い平行光。太陽と同じ uniform を使い、薄明では両方がほぼ0になる時刻で入れ替える。
- 影の向き（画面、高さ1pxあたり）: `v = −d / tan(max(e, 9°))`。長さは高さの2.5倍まで。夕方は東へ長く、正午は北へ短く落ちる。

### 5.3 光の式（lighting.js）
```
amb  = sky · (0.7 + 0.3·N.z)                        // 半球の空。上を向く面ほど空を受ける
sunT = sunColor · max(0, N·L) · S                    // S = 投影影（5.4）
loc  = Σ 局所光（既存: 減衰 × N·Ll × 壁遮蔽 × 高さ ray）
out  = albedo · (amb + sunT + loc) + spec + albedo·emis·1.5
```
gain は新しい資産では1.0（旧資産は移行期間だけ既存の値）。

### 5.4 投影影（太陽・月）
- 新しい native 解像度の `shadowCv`（R のみ使用、0 でクリア）。不透明な物（木・岩・構造物・人物・敵）ごとに、**その height 画像**を、足元の行を軸にして `setTransform(1, 0, −vx, −vy, footX, footY)` で傾け、`globalCompositeOperation='lighten'` で描く（地面に落ちる影の位置に、遮る物の高さの最大値が入る）。
- shader: 受ける画素の高さを hr として `q = p + (0, hr) + v·hr` を読み、`S = 1 − strength · smoothstep(1.5, 4, Hc − hr)`。人物が木陰に入れば暗くなり、木は自分の影で自分を暗くしない。
- 昼の強さは 0.75、月は 0.45、仰角10°以下では強さを下げる。
- 既存の太陽の高さ ray（8ステップ）は、太陽には使わない（局所光には残す）。
- 2D の楕円の接地影は、GL では「接触の遮蔽」として半径を小さく（ry 2）、alpha 0.18。方向を持つ影は shadowCv だけが作る。2D fallback では従来の楕円を v の向きにずらす。
- 近似の限界: 樹冠のように奥行きのある物の影は、足元を軸に傾けた形になり、完全な3Dではない。

## 6. 地面: 基本の土＋有機的なマスクで重ねる草＋細かな散らし

### 6.1 構成
- 新規モジュール `ground.js`（DOM 非依存の純関数＋焼き込み関数。canvas は引数で受け取る）。
- 地上マップの地面を、8×8タイル（256×256px）の**チャンク**に焼き込む。color・normal・height の3枚。LRU は最大24チャンク（約19MB）。1フレームに焼くのは1チャンクまで。地形が変わったら（`openWallTile`・`resetWorldTerrain` など）そのチャンクを捨てる。
- 層の順（下→上）: `soil`（全面）→ `path` → `sand` → `moss` → `grass` → `darkgrass`。水は既存の描画を残し、岸の形だけ同じマスクにする。farmland は既存の `drawFarmland` で上に重ねる。

### 6.2 マスク（白い線・格子の継ぎ目を作らない仕組み）
1. 材質 m のタイル中心の指示値 I_m ∈ {0,1} を、**ワールド座標で双線形補間**して c_m(p) を得る。値はタイルを跨いで連続する。
2. 継ぎ目のないノイズの素材（Workbench の資産 `mask_noise` 64×64・16階調、`mask_blade` 64×64）を、ワールド座標で2回、ずらして読む: `n = 0.6·T(p) + 0.4·T(swap(p) + (23,41))`。
3. `mask = c_m + 0.55·(n − 0.5) + 0.15·(blade − 0.5) > 0.5`。水際は振幅を 0.25 に下げる（歩ける陸に水が6px以上入り込まない）。
4. 縁の処理（方向を持たない）:
   - 草の内側1px: 「葉先」の色（基本より彩度を上げ、明度は同じか低い）。
   - 草の外側の土2px: 遮蔽として 8〜12% 暗くする（全方向で同じ）。
   - 高さ: 草は土より1.5px高い台。縁の1〜2pxを傾斜にし、太陽の向きによって東西南北のどの縁が光るかが変わる。
   - **禁止**: 縁の帯に、両側の材質の中央値より L* が3以上明るい画素を置かない（テストで検査）。
5. 32px 周期を消す: 材質の模様は 64×64 の継ぎ目なしの素材（`mat_soil` など）を、ワールド座標で読む。

### 6.3 素材（新しいシート `groundmat`。64×64、pivot [0,0]）
`mat_soil, mat_path, mat_sand, mat_moss, mat_grass, mat_darkgrass, mask_noise, mask_blade`。どれも継ぎ目なし、明度の幅は ±8 L* 以内、方向の光なし。高さと法線は §4.2 の shape で作る（小石＝小さな楕円体、ひび＝溝、草の塊＝blob）。

### 6.4 細かな散らし（拾える物とは別）
- チャンクを焼くときに、決定的な Poisson-disc で置き、color・normal・height に直接焼き込む。草: 葉の房（3〜5px）、クローバー、落ち葉。土: 小石（1〜3px）、小枝（3〜5px）。道: 締まった小石。
- 制限: 1つの大きさは 6×6px 以下、高さは 1.5 以下、地面との L* の差は 15 以下、輪郭なし、明るい黄白の色なし。
- 拾える物（branch / pebble / grass ノード・花・作物）: 10px 以上、濃色の輪郭の塊、接地影、近づくと光る、フォーカスで輪郭が付く。散らしにこれらのスプライトを流用しない。
- 既存の `drawDeco` の縮小した茂みと花は、密度を半分以下にし、大きさの規則を満たす物だけ残す。

### 6.5 地面の関門（G5）
機械: (1) 隣り合う2チャンクを別々に焼いた境界列と、2倍幅を1回で焼いた結果が byte 一致。(2) 同じ seed で決定的。(3) 草だけの領域で、32px のずれの自己相関が、0のずれの0.35倍以下。(4) 縁の明るい画素の禁止（6.2-4）。
画像: 正午・17:30・夜（灯あり）で、草と土の境が有機的であること。白い線とタイルの格子が見えないこと。散らしが拾える物と区別できること。

## 7. 当たり判定と足元の形の修正

### 7.1 方針
足元の当たりを**楕円（縦横比 2:1）**に統一する。実装は「dy を2倍にして円で押し出し、戻す」だけで、既存の `pushCircle` を少し変えるだけで済む。動く物（主人公・敵・住人）の半径 r は横の半径と解釈する。

### 7.2 値（初期値。§7.3 の計測で確定する）
| 対象 | 現在 | 新しい値 |
|---|---|---|
| 主人公の足元 | `P.radius` 10 を移動にも被弾にも使う | **新しい `P.footRadius = 7`**（靴の幅14px）を `moveEntity`・`resolveCollisions` だけに使う。**`P.radius` 10 は被弾判定用に残す**（`combat.js` 328/421/434/537/557 が `P.radius` を足しているため、変えると戦闘の難度が変わる） |
| 木（生きている） | r10、pivot | **r6**（幹の幅＋1）、pivot = 根元の中心 |
| 切り株 | r8 | r7 |
| 岩・鉱石 | r14 | 計測した接地の幅/2（目安 12） |
| 構造物の円 | 中心 `ty*32+16` | **中心 `ty*32+28`**（描く足元と同じ）。r はそのまま |
| 構造物の箱（壁など） | タイル全体 | そのまま（建築の格子のため） |

- フォーカス: 木の `hit: { w: 30, h: 56 }`（幹と樹冠の下部）。岩は計測した不透明部分の外接矩形にする。
- 反転した物は、足元のずれ dx を反転する（`node.flip` を見て `px` を補正）。まっすぐな幹の新しい木では dx = 0。

## 11. 未確定事項・危険

1. **参照の数値は目視の概算**（§0）。画素を計測していないため、§2.1 の比率は出発点。G1 で原寸を見て直す。1440×900（scale 2）では身長45px が約90px（画面高の約1割）になり、MineGeon より大きい。大きすぎて視界が狭く感じるなら、キャンバスはそのまま描く高さを帯の下側（43px）へ寄せる。
2. **住人の描き直しは必須**（P5c）。主人公だけ大きくなると、住人（32×48）が子供に見えるため。
3. **夜の時刻の変更**（§5.1）: 敵の窓を00:00〜06:48から21:00〜04:00へ動かす。長さはほぼ同じだが、プレイヤーが拠点へ戻る時刻が早くなる。出現数のテストは期待値だけで、実際の遊びの手触りは P3 の後に Codex が短いプレイで確認する。住人の帰宅など、区分を読む他の処理を見落とす危険がある（P3 で grep して確認）。
4. **C 案（薬草摘み）は今回の新案**で、帽子で顔が暗くなる弱点が比較板で目立つ可能性がある。
4. **投影影は近似**: 樹冠の奥行きは表せない。G3 で不自然なら、樹冠の影だけ楕円を足すなどの調整を P2 の中で行う。
5. **性能**: shadowCv の upload で、1フレームの GL の時間が増える。mobile で中央値 6ms を超えたら、影を半解像度にする。地面のチャンクを焼く時間は、初回に1チャンクあたり約10〜20ms と見込む（未測定）。
6. **移行期間**: 古い資産の焼き込み光は、gain で弱めるだけで消えない。描き直しが済むまで、新しい太陽の向きと矛盾する物が残る。G6 は、木・岩・主人公・地面の描き直しが済んでから行う。
7. **当たりの変更で手触りが変わる**: 足元の半径を10から7にすると、狭い所を通りやすくなる。被弾判定は `P.radius`（10のまま）を使い続けるので、戦闘の難度は変わらない想定（`combat.js` の5箇所で確認）。ただし、ノックバックと押し出し（`combat.js` 86/123 の `moveEntity(…, P.radius)`）も `footRadius` へ切り替える必要がある。プレイでの確認はしていない。`world.js:1241` の「自分が立っている」判定（`BALANCE.player.radius + 1`）は、足元の判定なので `footRadius` へ移す（P3 の所有ファイルに `world.js` のこの1行を含める）。
8. **シート名の一覧**: §4.5 の束の割り当ては、本書の作成時に `assets/manifest.json` を読み直していないため、名前が実際と違う可能性がある（Codex が P4 の前に確定する）。
