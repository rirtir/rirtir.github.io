# 地面の作り直し(TERRAIN_REWORK3)

**状態: 未実行。** この環境には実行手段がなく、`art/build_terrain3.py` も `ground.js` の変更もまだ一度も動かしていない。下の「root が確認すること」を実行して初めて結果が分かる。ここに書く数値・見た目はすべて設計上の意図であり、検証済みの結果ではない。

## 実際の契約(依頼文との違い)

- `art/terrain.json` は存在しない。実際に使われている地面素材は manifest の **`ground` シート**(`overrides: "tiles"`)。ソースは `art/ground.json`、法線/高さは `art/normalmaps/ground-{normal,height}.json`。
- `ground` は **8材質 × 6変種 = 48枚**(grass, darkgrass, dirt, path, sand, cave, moss, ruin。各 0〜5)、32×32、pivot 0,0、atlas 256×192(8列)、frameTags `default` 0〜47。依頼文の「12材質×4変種」ではない。名前・並び・サイズ・タグ・時間・列数は `--integrate` が既存の `assets/ground/atlas.json` と突き合わせ、1つでも違えば何も置き換えずに中止する。
- 水(water/deepwater)と畑(farmland)は `ground` に無く、`tiles` シートの旧タイルのまま。**畑の旧い黄色い帯は今回直らない**(manifest を触れないので `ground` に畑を足せない)。必要なら manifest 側の担当が `farmland0..5` を足す。

## 1. 色(草を明るく・土を静かに)

- 草は `#617b47` / `#6c894c` の系統(暗い影 `#4f663b`〜明 `#789452`)。darkgrass は少し暗く、moss は少し青緑。土は `#5a4838`〜`#7a614a` の泥色で、粒は低コントラスト。
- パレットはこの素材専用の40色。`art/palette.json` は64色で埋まっていて草色を足せないため(レビューで可否を判断してほしい)。固定パレット違反の警告が出る場合はここが原因。
- 影(焼き込みの陰)は入れない。材質ごとに4段+差し色1段。

## 2. 素材(中立アルベド・独立した法線/高さ)

- 色: 周期32pxの値ノイズ。広い形(macro)と細かい粒(grain)。草は2〜3枚の房(根元が暗く先が明るい)、土は低い小石を数個。黄色い短い棒・淡緑の丸斑・格子状の紙吹雪は作らない。
- 継ぎ目: 縁から2px以内は全変種で共通の成分だけ。違いは内側にだけ入るので、別の変種が隣り合っても繋がる(スクリプトが検査する)。
- 高さは色とは別の種のノイズ・形から作る。土=細かい粒の起伏、草=葉の小さな盛り上がり、cave/ruin=周期ボロノイの低い面(傾き±0.30/0.16 px/px)と境の溝。法線は高さの勾配から、`build_normal_maps` の量子化ベクトルへ丸める。
- 高さの画素: R=px/64×255(0〜4px、0.25px刻み)、G=粗さ0.8、B=gain 1.0(中立)。アルファは全面不透明。
- **`art/build_normal_maps.py --sheet ground` を実行しないこと**。色の分類から高さを作り直して、この法線/高さを上書きする。

## 3. ground.js

- 散らし(scatter)の密度: 種類ごとの世界座標の低周波マスク(塊の外は0.05倍、中は最大約2.2倍)。dirt/path は同じ材質に囲まれた3×3タイルの中心ほど静か(最大0.12倍)、草は他材質との境で房が増える。座標の特別扱いは無く、材質の近傍とノイズだけで決まる。
- 草と土の境: ① 草の葉先が主マスクの外へ約0〜3px、まばらに出る ② 縁の内側に土が少し覗く ③ 縁の暗い遮蔽(AO)を斑にした(従来は縁全体が連続していた)。白縁・暗い輪郭線は無い。葉先・土は同じ画素の color/normal/height を読むので3枚とも同じ形。
- 葉先・覗く土・斑のAOは `scatter !== false` の時だけ(`cosmetic`)。既存テストが `scatter:false` の平坦色で「平坦色より8%を超えて明るい画素が境界に無い」を検証しているため、素の境界はそのまま残してある。
- 変えていない物: `bakeRegion` の分割非依存性(すべて世界座標のノイズ・タイル格子だけ)、`matOut`(勝った材質。葉先でも変えない)、カメラ・時刻への依存なし、新しい当たり判定・ノードなし。近傍の読み取りは±1タイルで、領域の外へ2タイルある余白の中に収まる。

## root が確認すること(順番どおり)

1. `python art/build_terrain3.py` — 例外が出ないか、`.review/v3/terrain-production/` の `mosaic-albedo`(草が暗い緑のままでないか、土が帯状でないか)、`mosaic-normal`、`mosaic-height`、各 `albedo/normal/height` の contact を**実際に画像で**見る。標準出力の「検査」が問題なしか。
2. ブラウザで既存の616件(継ぎ目・分割テスト含む)を実行。`tests/visual_rework3.js` の地面テストは特に。
3. 見た目に問題が無ければ `python art/build_terrain3.py --integrate`。実機の昼夜・拡大率で、樹冠・影・低木が沈まないか、道の中心が静かか、草の境が切り抜きに見えないかを確認する。
4. 不合格なら `art/build_terrain3.py` の `RAMPS`(色)・`SPEC`(しきい値・起伏)だけを調整して1へ戻る。

## 限界

- Workbench の API は既存スクリプト(`build_tree3_demo.py`, `build_normal_maps.py`)の使い方を写しただけで、実行して確かめていない。`export` が書くファイル名(`atlas.json`)や frameTags の既定値が想定と違えば、`--integrate` は契約検査で止まる(止まるのが正しい動き)。
- 材質の見た目(色の段の割合・起伏の強さ)は初期値で、実画像でのチューニングはしていない。
- 統合は「全部を `.new` へ置いてから置き換える」だが、複数ファイルの置き換えは完全なトランザクションではない。失敗したら git で戻す。
- `assets/ground/` の `contact.png`・`review.*`・`static.gif` などの確認用ファイルは更新しない(古いまま)。
