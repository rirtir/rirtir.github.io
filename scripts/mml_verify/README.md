# MML 演奏検証ツール（マビノギモバイルで「鳴らない音」を調べる）

MML をゲームで演奏したときに、**どの音が鳴らなかったか**を、録音から自動で調べて、
たまった結果から**どんな条件で鳴らなくなるか**の法則を探す道具です。
（Web ではなく、パソコン上の Python で動きます。録音や結果は公開されません。）

あなたがやること：**MML をゲームに貼り付けて演奏する**。それ以外（録音の開始・停止、解析、記録、法則探し）は自動です。

## 準備（最初の1回）

```
pip install soundcard          # 録音に使う（すでに入れてあります）
```
- 録音ファイル（OBS の録画など）を読むために `ffmpeg` が使える必要があります（すでに使えます）。
- Python 3.11、numpy / scipy / soundfile / matplotlib / pyperclip が必要です（すでに入っています）。

### 録音先を覚えさせる（最初の1回）
ゲームの音が出ている出力先は、パソコンによって違います。次を実行して、**ゲームで何か音を出し続けて**ください。
```
python scripts/mml_verify/run.py calibrate
```
全部の出力先を同時に録音して、音が出ている所を探し、`.local/mml_verify/config.json` に覚えます。
（一覧は `run.py devices`。うまくいかないときは `--device 番号` で指定できます。）

## 1回の検証の流れ

```
python scripts/mml_verify/run.py run                    # クリップボードの MML を検証
python scripts/mml_verify/run.py run --probe 08_dense16  # 検証用の MML を使う（自動でコピーされる）
python scripts/mml_verify/run.py run --file my.txt       # テキストファイルの MML
```
1. **実行すると、すぐ録音が始まります。**
2. ゲームの作曲画面に MML を貼り付けて、**演奏**します。
3. 演奏が終わって**静かになると、自動で停止**して解析します（4秒の無音で。変えるには `--auto-stop 秒`、止めたくなければ `--no-auto-stop` で、止めるときは Enter キー）。
4. 画面に結果が出ます。
   - **鳴らなかった音**の一覧（パート・何番目・音名・時刻・MML の文字位置）
   - 詳しい図 `.local/mml_verify/sessions/<日時>/report.html`（スペクトログラムの上に、鳴った音は緑・鳴らなかった音は赤で重ねて表示。MML の該当部分も赤く表示）
5. 結果は自動で `.local/mml_verify/results.jsonl` にたまります。

メモを残したいとき： `--note "楽器=マンドリン、BGMなし"` （条件を変えたときに、あとで見返せます）

**同じ MML を何回も演奏して、毎回同じ音が抜けるか見たいとき**： `--repeat` を付けると、終わるたびに「もう一度？」と聞かれます。
```
python scripts/mml_verify/run.py run --probe 08_dense16 --repeat
```

**検証用の MML を順番に全部やる**（音の高さ・連打・速さ・同時に鳴る数…を、1つずつ変えたもの）：
```
python scripts/mml_verify/run.py probes                      # 一覧を見る
python scripts/mml_verify/run.py run --all-probes            # 順番に全部（1つ終わるごとに Enter で次へ）
python scripts/mml_verify/run.py run --all-probes --start-from 08_dense16   # 途中から
```

すでにある録音（OBS の録画など）を解析するだけなら：
```
python scripts/mml_verify/run.py analyze "録画.mkv" --file my.txt
```

## 法則を探す

```
python scripts/mml_verify/run.py patterns
```
たまった結果から、次を出します（`.local/mml_verify/patterns.txt` にも保存）。
- **再現性**：同じ MML を複数回演奏したとき、毎回抜ける音／たまに抜ける音／毎回鳴る音。
  「毎回抜ける割合」が 100% に近ければ、楽譜（条件）で決まっている＝法則があるということです。
- **一番よく分ける条件**：「直前1秒に始まった音の数が 10 以上だと鳴らなかった率が 23%、未満だと 0%」のような形で。
- **決定木のルール**：条件を組み合わせた「こういうとき鳴らない」。
- **条件ごとの鳴らなかった率**：音の高さ・長さ・テンポ・パート・同時に鳴る数・余韻が残っている音の数など。

調べている条件（特徴量）は `features.py` にあります。足したい条件があれば追加できます。

**使い方のコツ**
- まず `01_scale`（半音階）→ `02_repeat`（連打）→ `03_speed_*`（速さ）→ `04〜06`（2パート）→ `07〜10`（3パート・負荷）の順がおすすめです。**1つずつ条件を変えてある**ので、原因を切り分けやすいです。
- 最後に `20_random*`（ランダムな曲）をたくさん集めると、条件が混ざった状態での統計が取れます。
- 鳴らなかった音が少ないうちは、法則は偶然かもしれません。`patterns` は「件数が少ない」と注意を出します。
- 「相関があること」と「それが原因であること」は別です（例：速い曲はたいてい音数も多い）。怪しい条件が見つかったら、その条件だけを変えた MML を作って確かめてください。

## 解析の精度を上げる（音色を覚えさせる）

標準では、ゲームのマンドリン（C4〜C5 あたりを実測した音色）を基準に判定します。
別の楽器にした場合や、低い音・高い音で精度が落ちる場合は、**全部の音が鳴った録音**から音色を覚えさせられます。
```
python scripts/mml_verify/run.py learn "録音.wav" --probe 01_scale     # 半音階がすべて鳴った録音
python scripts/mml_verify/run.py learn --reset                        # 覚えた音色を消す
```
（疑似録音での試験では、音色が違うとき、覚えさせると誤報が 9 個 → 0 個に減りました。）

## 判定の見かた

| 表示 | 意味 |
|---|---|
| 鳴った / 鳴らなかった | 確かな判定 |
| 鳴った? / 鳴らなかった? | **確かさが低い**。「同じ高さの音が近くにある（連打・ユニゾン）」か「低い音（C3より下）」 |
| 判定不能 | どちらとも言えない |

`patterns` の統計は、**確かな判定だけ**を使います（`--include-low` で低い確かさも含める）。

### 限界
- 低い音（約 C3 より下）は、半音の間隔が狭すぎて分けにくいので、確かさを低くしています。
- 同じ高さの音が近くにあるとき（連打・複数パートのユニゾン）は、録音の上で区別しにくいです。
- ゲームの BGM・効果音が演奏中に鳴ると、精度が下がります（BGM は止めておくのがおすすめ）。
- 音が「鳴らなかった」のか「音程が違う」のかは区別していません（その高さの音が鳴らなければ「鳴らなかった」になります）。

## 仕組み（簡単に）
1. `mmlparse.py`：MML を読んで、各音が何秒に鳴るはずかを計算。
2. `recorder.py`：ゲームの音（パソコンから出ている音）を録音。
3. `detect.py`：録音のスペクトルと楽譜を突き合わせ、①演奏の開始時刻（と時間のずれ）を求め、②その時刻に鳴るはずの音の高さだけを候補にしてスペクトルを分解し、③各音の始まりで強さが立ち上がったかを見る。
4. `features.py`：各音の条件（同時に鳴る数・余韻が残っている音の数・高さ・長さ…）を計算。
5. `report.py` / `patterns.py`：結果の表示と、法則探し。

## 動作の確認
```
python scripts/mml_verify/selftest.py                     # 疑似録音で精度を測る
python scripts/mml_verify/tests/e2e_synthetic.py          # 解析→記録→法則探しを通して確認
python scripts/mml_verify/tests/live_loopback.py          # 実際にスピーカーから鳴らして録音→解析（短く小さい音で鳴ります）
```
疑似録音（ゲームのマンドリンの実測値で合成）での試験結果：確かな判定だけを見ると、抜けた音を見逃さず、誤報もほぼゼロでした。
実機の確認（スピーカーから鳴らした音を録音）でも、抜いた1音を見つけられました。**本物のゲームの録音での精度は、まだ確かめていません**（最初の数回は、`report.html` の図で目視して確かめてください）。

## 保存される場所
`.local/mml_verify/`（Git には入りません）
- `config.json`（録音先・覚えた音色） / `results.jsonl`（全結果） / `patterns.txt`
