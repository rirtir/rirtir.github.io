# MML 演奏検証ツール（マビノギモバイルで「鳴らない音」を調べる）

MML をゲームで演奏したときに、**どの音が鳴らなかったか**を、録音から自動で調べて、
たまった結果から**どんな条件で鳴らなくなるか**の法則を探す道具です。
（Web ではなく、パソコン上の Python で動きます。録音や結果は公開されません。）

あなたがやること：**MML をコピーして、ゲームに貼り付けて演奏する**。それ以外（録音の開始・停止、解析、記録、法則探し）は自動です。

## ダブルクリックで使う（このフォルダの .bat）

| ファイル | 何をするか |
|---|---|
| **`MML検証_開始.bat`** | クリップボードの MML を検証。**開くとすぐ録音が始まる** → ゲームで貼り付けて演奏 → 静かになると自動で解析。終わると「もう一度？」と聞かれる（同じ MML の再現性を見られる） |
| `MML検証_検証用MMLを順番に全部.bat` | 検証用の MML を、1つずつ自動でコピーしながら順番に検証。1つ終わるごとに Enter で次へ（`q` で終了） |
| `MML検証_法則を探す.bat` | たまった結果から、鳴らなかった音の法則を探す |
| `MML検証_最新の結果を開く.bat` | 最新の結果の図（report.html）をブラウザで開く |
| `MML検証_録音先を探す.bat` | 録音先を手動で探して覚える（ふつうは不要。下記） |

**基本の流れ**：MML をコピー（Webツールの「全部コピー」など）→ `MML検証_開始.bat` をダブルクリック → ゲームに貼り付けて演奏 → 結果が表示される。

- **録音先は自動で決まります。** 最初の1回は、全部の出力先を同時に録音して、一番音が大きかった所を自動で選び、覚えます（次回からはそれだけを録音）。
- 演奏が終わって約4秒静かになると自動で停止します。すぐ止めたいときは、そのウィンドウで Enter キー。
- 事前に必要なもの：`pip install soundcard`（導入済み）。Python 3.11 と numpy / scipy / soundfile / matplotlib / pyperclip、ffmpeg。

## 「3パートそろってから抜ける」を確かめる検証用 MML

「音が抜けるのは、メロディ・和音1・和音2の3つがそろってから」という観察を、確かめるための検証用 MML を、**一番最初**に並べてあります。
同じ音の中身を、パートの組み合わせや割り当てを変えて鳴らします。

| 名前 | 内容 | 予想（観察どおりなら） |
|---|---|---|
| `00a_melody_chord1` | メロディ＋和音1（2パート） | 抜けない |
| `00b_melody_chord2` | メロディ＋和音2（和音1は休符） | 抜けない？ |
| `00c_chord1_chord2` | 和音1＋和音2（メロディは休符） | 抜けない？ |
| `00d_all3` | 3パートとも | 抜ける |
| `00e_perm_*` | 3パートの中身を入れ替え（5通り） | 抜ける音が「中身」についてくるか、「パート」についてくるかが分かる |

`MML検証_検証用MMLを順番に全部.bat` を実行すると、この順に進みます。1つずつ試すなら `run.py run --probe 00d_all3`。
結果は `MML検証_法則を探す.bat` で、「同時に鳴っているパートの数・組み合わせ」ごとの鳴らなかった率として出ます。
（`01_scale` 以降は、音の高さ・連打・速さなど、ほかの条件を1つずつ変えたものです。）

## コマンドで使う場合

```
python scripts/mml_verify/run.py run                      # クリップボードのMMLを検証
python scripts/mml_verify/run.py run --probe 00d_all3      # 検証用のMML（自動でコピーされる）
python scripts/mml_verify/run.py run --file my.txt         # テキストファイルのMML
python scripts/mml_verify/run.py run --repeat              # 同じMMLを続けて何回も
python scripts/mml_verify/run.py run --all-probes          # 検証用MMLを順番に全部
python scripts/mml_verify/run.py probes                    # 検証用MMLの一覧
python scripts/mml_verify/run.py analyze 録画.mkv --file my.txt   # すでにある録音（OBSの録画など）を解析
python scripts/mml_verify/run.py patterns                  # 法則を探す
python scripts/mml_verify/run.py learn 録音.wav --probe 01_scale  # 音色を覚えさせる（下記）
python scripts/mml_verify/run.py devices | calibrate | open-latest
```
メモを残すには `--note "楽器=マンドリン"`。自動停止の秒数は `--auto-stop 秒`、使わないなら `--no-auto-stop`。

## 結果の見かた

画面に、**鳴らなかった音**の一覧（パート・何番目・音名・時刻・MML の文字位置）が出ます。
詳しい図は `.local/mml_verify/sessions/<日時>/report.html`：スペクトログラムの上に、鳴った音は緑・鳴らなかった音は赤で重ねて表示し、MML の該当部分も赤く表示します。
結果は自動で `.local/mml_verify/results.jsonl` にたまります。

| 表示 | 意味 |
|---|---|
| 鳴った / 鳴らなかった | 確かな判定 |
| 鳴った? / 鳴らなかった? | **確かさが低い**。「同じ高さの音が近くにある（連打・ユニゾン）」か「低い音（C3より下）」 |
| 判定不能 | どちらとも言えない |

## 法則を探す

`patterns`（または `MML検証_法則を探す.bat`）が、確かな判定だけを使って、次を出します（`.local/mml_verify/patterns.txt` にも保存）。
- **再現性**：同じ MML を複数回演奏したとき、毎回抜ける音／たまに抜ける音／毎回鳴る音。「毎回抜ける割合」が 100% に近いほど、楽譜（条件）で決まっている＝法則があるということです。
- **一番よく分ける条件**：「同時に鳴っているパートの数が 3 以上だと鳴らなかった率が 20%、未満だと 0%」のような形で。
- **決定木のルール**：条件を組み合わせた「こういうとき鳴らない」。
- **条件ごとの鳴らなかった率**：パート数・同時に鳴っているパートの組・音の高さ・長さ・テンポ・パート・余韻が残っている音の数など。

調べている条件は `features.py` にあります。足したい条件があれば追加できます。

**コツ**
- 鳴らなかった音が少ないうちは、法則は偶然かもしれません。`patterns` は件数が少ないと注意を出します。
- 「相関があること」と「原因であること」は別です。怪しい条件が見つかったら、その条件だけを変えた MML で確かめてください。
- 最後に `20_random*`（ランダムな3パートの曲）をたくさん集めると、条件が混ざった状態での統計が取れます。

## 解析の精度を上げる（音色を覚えさせる）

標準では、ゲームのマンドリン（C4〜C5 あたりを実測した音色）を基準に判定します。
別の楽器にした場合や、低い音・高い音で精度が落ちる場合は、**全部の音が鳴った録音**から音色を覚えさせられます。
```
python scripts/mml_verify/run.py learn 録音.wav --probe 01_scale     # 半音階がすべて鳴った録音
python scripts/mml_verify/run.py learn --reset                        # 覚えた音色を消す
```
（疑似録音での試験では、音色が違うとき、覚えさせると誤報が 9 個 → 0 個に減りました。）

## 限界
- 低い音（約 C3 より下）は、半音の間隔が狭すぎて分けにくいので、確かさを低くしています。
- 同じ高さの音が近くにあるとき（連打・複数パートのユニゾン）は、録音の上で区別しにくいです。
- ゲームの BGM・効果音が演奏中に鳴ると、精度が下がります（BGM は止めておくのがおすすめ）。
- 音が「鳴らなかった」のか「音程が違う」のかは区別していません。
- **本物のゲームの録音での精度は、まだ確かめていません。** 最初の数回は、`report.html` の図で目視して確かめてください。

## 仕組み（簡単に）
1. `mmlparse.py`：MML を読んで、各音が何秒に鳴るはずかを計算。
2. `recorder.py`：ゲームの音（パソコンから出ている音）を録音（Windows の WASAPI ループバック）。
3. `detect.py`：録音と楽譜を突き合わせ、①演奏の開始時刻（と時間のずれ）を求め、②その時刻に鳴るはずの音の高さだけを候補にしてスペクトルを分解し、③各音の始まりで強さが立ち上がったかを見る。
4. `features.py`：各音の条件（同時に鳴るパートの数・組・余韻が残っている音の数・高さ・長さ…）を計算。
5. `report.py` / `patterns.py`：結果の表示と、法則探し。


## 保存される場所
`.local/mml_verify/`（Git には入りません）
- `config.json`（録音先・覚えた音色） / `results.jsonl`（全結果） / `patterns.txt`
- `sessions/<日時>/`：`rec.wav`（録音）、`report.html`、`report.txt`、`result.json`
