# MML 演奏検証ツール（マビノギモバイルで「鳴らない音」を調べる）

MML をゲームで演奏したときに、**どの音が鳴らなかったか**を録音から自動で調べ、
たまった結果から**どんな条件で鳴らなくなるか**を探す道具です。（パソコン上の Python で動きます。録音や結果は公開されません。）

あなたがやること：**MML をコピーして、ゲームに貼り付けて演奏する**。それ以外（録音の開始・停止、解析、記録、法則探し）は自動です。

## ダブルクリックで使う（このフォルダの .bat）

| ファイル | 何をするか |
|---|---|
| **`MML検証_3パート検証セット.bat`** | 検証用の**長い3パート曲（約1分）6曲**を、1曲2回ずつ、順番に演奏して検証。MMLは自動でコピーされるので、ゲームに貼り付けて最後まで演奏するだけ |
| **`MML検証_開始.bat`** | **自分の曲**を検証（実際に音が抜けた曲がおすすめ）。MMLをコピーして開くとすぐ録音が始まり、演奏後に自動で解析。終わると「もう一度？」と聞かれる（同じ曲で毎回同じ音が抜けるかを見られる） |
| `MML検証_法則を探す.bat` | たまった結果から、鳴らなかった音の条件を探す |
| `MML検証_最新の結果を開く.bat` | 最新の結果の図をブラウザで開く |
| `MML検証_録音先を探す.bat` | 録音先を手動で探す（ふつうは不要。初回は自動で決まります） |
| **`MML検証_最初の準備（音色を覚える）.bat`** | **最初に1回だけ**。半音階（1パート）を演奏して、ゲームの**音域ごとの音色と音の大きさ**を覚える。これをやらないと、判定がずれます（下記） |
| `MML検証_仮説の確認.bat` | 「同じ音域の音が同時に始まると前のパートの音が抜ける」という仮説を確かめる、短い曲（25秒）7曲を、1曲2回ずつ |

演奏が終わって約4秒静かになると、自動で録音が止まります。すぐ止めたいときは、そのウィンドウで Enter キー。

**途中でやめても大丈夫です。** 曲を順番にやる `.bat`（検証セット・仮説の確認）は、終わった分が残っていて、次に起動すると**自動で続きから**始まります（最初からやり直すときは、`.bat` の `run.py` の行の最後に `--again` を付けます）。

## 最初にやること（重要）
ゲームの音は、**音域によって音色も音の大きさも大きく違います**（実測：E4〜E5あたりは、ほかの音域より音量が約1/3〜1/5で、倍音の出方も違う）。
`MML検証_最初の準備（音色を覚える）.bat` で、半音階を1回演奏して覚えさせると、判定がかなり正確になります。
覚えさせたあとで、それまでの録音を解析し直すには：`python scripts/mml_verify/run.py reanalyze`（録音は残してあるので、いつでもやり直せます）。

## 検証用の曲について
- 3パート（メロディ・和音1・和音2）が**常に動いている**、約1分・約450音の曲が6曲あります（テンポは 90〜150）。
- 1曲の中に、**重なり方のパターンを順番に8種類**入れてあります：同時に始まる（4分・8分・16分）／ずらして入る／2つ伸ばして1つ動く／1つ伸ばして2つ動く／短く切る／3つがバラバラの長さ／ランダム。
- 同じ高さの音が近くに重ならないようにしてあります（録音で判定しやすくするため）。
- MML は約2,000〜2,300文字です。**貼り付けられなかったら教えてください**（短くします）。
- 結果には「どのパターンの区間で抜けたか」が残るので、`法則を探す` で、パターンごとの抜けやすさが分かります。

## 結果の見かた
画面に**鳴らなかった音**の一覧（パート・何番目・音名・時刻・MMLの文字位置）が出ます。
詳しい図は `.local/mml_verify/sessions/<日時>/report.html`（スペクトログラムの上に、鳴った音は緑・鳴らなかった音は赤。MMLの該当部分も赤）。

| 表示 | 意味 |
|---|---|
| 鳴った / 鳴らなかった | 確かな判定 |
| 鳴った? / 鳴らなかった? | 確かさが低い（同じ高さの音が近くにある／低い音） |

## 法則を探す
`法則を探す` が、確かな判定だけを使って次を出します（`.local/mml_verify/patterns.txt` にも保存）。
- **再現性**：同じ曲を複数回演奏したとき、毎回抜ける音／たまに抜ける音。100% に近いほど、楽譜（条件）で決まっている。
- **一番よく分ける条件**、**条件を組み合わせたルール**、**条件ごとの鳴らなかった率**（パターン・パート数・同時に鳴るパートの数・音の高さ・長さ・直前に始まった音の数など）。
- 鳴らなかった音が少ないうちは法則は偶然かもしれません（件数が少ないと注意が出ます）。相関と原因は別なので、怪しい条件が見つかったら、その条件だけを変えた曲で確かめます。

## 解析の精度について
- 疑似録音（ゲームのマンドリンの実測値で合成し、わざと音を抜いたもの）では、確かな判定について、見逃し・誤報とも0でした。実機の経路（スピーカーから鳴らして録音）でも、抜いた1音を見つけられました。
- **本物のゲームの録音での精度は、まだ確かめていません。** 最初の数回は `report.html` の図で目視してください。
- 低い音（約C3より下）と、同じ高さの音が近いときは、区別しにくいので「確かさ低」にしています。
- 演奏中にBGM・効果音が鳴ると精度が下がります（BGMは演奏中は鳴らないとのこと）。
- 音色が合わないときは、全部の音が鳴った録音で `run.py learn 録音.wav --probe 名前` を実行すると、ゲームの音色を覚えます。

## コマンドで使う場合
```
python scripts/mml_verify/run.py run                       # クリップボードのMMLを検証
python scripts/mml_verify/run.py run --probe R1_t110       # 検証用の曲を1つ
python scripts/mml_verify/run.py run --all-probes          # 長い3パート曲を順番に（--times 1 で1曲1回）
python scripts/mml_verify/run.py run --all-probes --set short   # 短い3パート曲（12個）
python scripts/mml_verify/run.py probes                    # 検証用MMLの一覧（★が既定のセット）
python scripts/mml_verify/run.py analyze 録画.mkv --file my.txt # すでにある録音（OBSの録画など）を解析
python scripts/mml_verify/run.py patterns | open-latest | devices | calibrate | learn
```

## 仕組み
`mmlparse.py`（MML→各音の予定時刻）→ `recorder.py`（ゲーム音を録音）→ `detect.py`（録音と楽譜を突き合わせ、①演奏の開始時刻、②その時刻に鳴るはずの音の高さだけでスペクトルを分解、③各音の始まりで立ち上がったかを判定）→ `features.py`（各音の条件）→ `report.py` / `patterns.py`（結果表示・法則探し）。
動作確認：`selftest.py`、`tests/` の `e2e_rich.py`・`e2e_synthetic.py`・`live_loopback.py`・`live_autopick.py`・`learn_effect.py`。

## 保存される場所
`.local/mml_verify/`（Git には入りません）： `config.json`、`results.jsonl`（全結果）、`patterns.txt`、`sessions/<日時>/`（`rec.wav`、`report.html` ほか）
